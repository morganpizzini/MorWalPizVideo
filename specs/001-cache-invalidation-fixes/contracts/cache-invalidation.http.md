# Contract: Cache Invalidation HTTP Endpoints

**Feature**: `001-cache-invalidation-fixes`
**Owner**: `MorWalPizVideo.ServerAPI` (server) and `MorWalPizVideo.BackOffice` (sole internal client)
**Status**: Stable contract; this feature aligns the BackOffice client to it.

---

## Endpoint: Reset in-memory cache keys

```
GET /api/cache/reset?k={key[,key,...]}
```

- **Auth**: same as existing (server-internal call; not exposed to public callers).
- **Query parameters**:
  - `k` (optional, string): comma-separated list of in-memory cache keys to remove. Each key is normalized to lowercase before lookup. If omitted, the server resets a default set (matches, products, sponsors, pages, calendarEvents, bioLinks, shortLinks).
- **Response**: `204 No Content` on success.
- **Errors**: standard 5xx on server fault. There is no documented 4xx for an unknown key (unknown keys are no-ops).

**Client expectation (BackOffice)**:
- Always supply `k` with one or more values.
- Treat any non-2xx as a failure of the cache subsystem; the calling controller MUST still report the underlying data write outcome accurately to the SPA (e.g., do not surface a 500 to the user if the data write succeeded but cache invalidation failed — log the cache failure instead).

---

## Endpoint: Evict output cache by tag

```
GET /api/cache/purge?k={tag}
```

- **Auth**: same as existing.
- **Query parameters**:
  - `k` (required, string): the output cache tag to evict. Server normalizes via `ToLowerInvariant` before invoking `IOutputCacheStore.EvictByTagAsync` (new behavior in this feature).
- **Response**: `204 No Content` on success.
- **Errors**: standard 5xx on server fault.

**Client expectation (BackOffice)**:
- Issue exactly: `GET cache/purge?k={Uri.EscapeDataString(tag)}` against the `MorWalPiz` named HttpClient (which is configured with `{SiteUrl}api/` as `BaseAddress`).
- **This is the regression fix**: the previous client implementation used `GET cache/purge/{tag}` (path segment), which 404s against this contract.
